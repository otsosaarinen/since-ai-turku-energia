# Harness (second prediction method)

Copied from https://github.com/rogue-agent/livelectroray at commit b44314d893 (reviewed read-only on 7 Nov 2026; no licence file upstream, ask the author before publishing).
Run it from this folder with the project environment: `uv run --group harness python harness.py -p llamacpp -m <model> -q "<question>"`, see the main README.
Safety: the `run_python` tool runs model-written code with your full user access. Keep API keys out of `key.txt` unless you accept that.
Fingrid key: `harness/key.txt` with a line `FINGRID_API_KEY=...` (git-ignored). Local model: Llama app on `http://localhost:9931/v1`, pass `-m <model id>` (list with `curl localhost:9931/v1/models`).
Test results and limits: `EXPERIMENTS.md` section 8. Do not commit `answer*.txt` or `reports/` (git-ignored).
Changes to the upstream code (copied at b44314d): the files were reformatted by the editor (formatting and unused imports only); `harness.py` got a `--progress` flag (or `HARNESS_PROGRESS=1`) A tool call whose JSON arguments are cut off or invalid no longer crashes the run: the error is returned to the model so it can retry; such retries have their own budget (4 per run) and do not use up the 10 tool turns. `get_data` and `fetch_url` results are saved to `harness/reports/data/` (git-ignored) and the model gets a 1200-character preview plus the file path, with an extra rule in the system prompt to load the file in `run_python` instead of pasting data into code. After each model turn `harness.py` also logs the model's full reasoning (`reasoning_content` or `reasoning` field of the reply) as a `[think] <json string>` progress line; the website shows it under the step.
